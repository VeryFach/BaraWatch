# Troubleshooting

Never paste API keys, credentials, authorization headers, or complete key-bearing request URLs into tickets or logs.

| Symptom | Likely cause | Safe diagnostic | Non-destructive resolution |
|---|---|---|---|
| Protected endpoint returns 503 for missing key | Server key is unset; auth differs by route and environment | Check only presence/length without printing: `python -c 'from app.core.config import Settings; s=Settings(); print(bool(s.ai_internal_key), len(s.ai_internal_key) >= 32)'` | Configure a strong key in local `.env`/deployment secret store; restart service and update trusted server caller |
| Protected endpoint returns 401 | Header absent/incorrect, wrong header name, or caller uses a different key | Confirm caller sends the expected header name (`X-Internal-Key` or vision `X-API-Key`) without logging value | Correct server-side secret wiring; do not put key in browser code |
| Pydantic returns 422 for dates | Missing/invalid ISO date or date ordering/period-length rule failed | Review request dates only; burn dates must satisfy `pre_start < pre_end <= post_start < post_end`, each interval ≤90 days | Correct request payload and timezone on datetime fields; retry with a valid request |
| Burn-area returns 422 `No usable imagery` | No scene under cloud/date filters, missing required band, unusable rasters, or no common clear pixels | Inspect sanitized structured logs for scene selection/unusable reasons and pixel counts | Verify date windows, CDSE assets and cloud metadata; retry only after diagnosing. Do not convert to a successful zero-area result |
| Burn-area returns 503 and logs `ConnectError`/DNS error | STAC host cannot resolve/reach network; code default is legacy STAC URL | Check DNS/HTTPS to the configured catalog without credentials; inspect `COPERNICUS_STAC_URL` presence, not `.env` contents | Restore network/DNS and verify configured host against current [CDSE STAC docs](https://documentation.dataspace.copernicus.eu/APIs/STAC.html); endpoint code/config update is a separate change |
| S3 403 / authentication failure | CDSE S3 keys missing, expired, mistyped, or access denied | Check whether both env variables are set without echoing values; verify credential status in CDSE account | Generate/rotate credentials at CDSE and update secret store; restart process |
| B8/B12/SCL read error or zero valid pixels | Asset alias unavailable, raster extent not covering ROI, corrupt download, nodata/resampling or SCL mask removed all valid pixels | Review sanitized scene IDs and band valid-pixel counts; compare band coverage and requested ROI | Confirm scene assets/date coverage; rerun after transient network errors. Avoid changing mask or offset until source data confirms a bug |
| Few scenes pass cloud filtering | Scene cloud metadata exceeds configured `max_cloud_percent` or dates have sparse coverage | Log selected scene IDs and request cloud/date constraints | Select a scientifically appropriate wider window or cloud limit and report the limitation; do not force a threshold for a desired result |
| Docker command says daemon/socket unavailable | Docker Engine/Desktop is stopped or current user cannot access daemon | `docker info` (does not print app secrets) | Start Docker Desktop/Engine or use an authorized Docker host; rerun Compose checks |
| `ModuleNotFoundError: boto3`, `rasterio`, or `pyproj` | Optional Copernicus requirements were not installed in local venv | `./.venv/bin/python -m pip show boto3 rasterio pyproj` | From service directory install `./.venv/bin/python -m pip install -r requirements-copernicus.txt` |
| Cache disk usage grows or a cached file fails to open | Cache has no eviction and reuse check accepts any nonzero file | `du -sh "${BURN_AREA_CACHE_DIR:-/tmp/barawatch-burn-area-cache}"` | Stop requests and preserve cache before cleanup; remove only confirmed regenerable cache files under the configured cache directory. Do not point the cache path at user data |
| Vision returns 503 for checkpoint | A model path is missing or unreadable | Check file existence/permissions for configured model paths without uploading weights | Provision approved checkpoints at the configured local paths and restart/retry; do not assume a model download fallback |
| Vision returns 503 inference unavailable | Runtime/model/device initialization error | Inspect sanitized application traceback and device configuration | Verify compatible runtime, available memory and `BARAWATCH_DEVICE`; test CPU if appropriate |
| FIRMS helper reports MAP_KEY missing or HTTP error | Missing/invalid key, unsupported product, invalid bbox/date or provider outage/quota | Check key presence only; validate source allowlist, bbox ordering, 1–5 day range; inspect provider status | Set or rotate `FIRMS_MAP_KEY` securely; wait/check provider quota or retry after outage. Avoid printing downloader URL because key is in its path |
| FIRMS returns HTML instead of CSV | Authentication/rate/error page returned by provider | Inspect only response content type/status and a safely redacted error | Verify key/product and provider status; do not parse HTML as hotspot data |
| Compose vision path cannot write weights | Host model directory empty or host file not readable | `ls -l models/weights/` | Put approved local weights in that directory; file is mounted read-only into container by design |
| `save_geotiff=true` fails under Compose | Root filesystem is read-only and no output volume is mounted | Check filesystem permission error and current `BURN_AREA_OUTPUT_DIR` setting | Configure/mount a dedicated writable output path in deployment as a separately reviewed infrastructure change |
